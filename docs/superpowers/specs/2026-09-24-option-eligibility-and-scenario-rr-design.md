# 期权合约筛选与情景盈亏比设计

## 目标

在不改变商品标的筛选、排序和机会分组的前提下，统一具体期权合约的推荐口径。低流动性或商品状态不支持的合约不能被其他高分补偿，但对应商品仍完整保留。同时利用商品支撑/压力位、到达目标所需时间和期权定价参数，计算期权目标价、止损情景价值与盈亏比，重点识别 `START` 和 `PREPARE` 阶段的高盈亏比机会。

本次只使用项目已经具备的日线期权数据、商品决策和本地支撑压力位。没有实时期权买卖盘口时，结果仍是收盘研究值，不宣称可以按该价格成交。

## 评分分层

系统不再用一个总分同时表达所有含义，而是按以下顺序处理：

1. **商品标的层**：`dir_score`、`state_v2`、`structure_confirm` 决定商品自身的排序与机会分组；禁止读取期权资格、期权量仓或期权链是否存在来改变结果。
2. **期权合约推荐层**：商品展示完成后，成交量、持仓量、方向、阶段、结构和数据完整性只决定具体合约是否推荐。
3. **标的发动机**：只使用RPS、ADX、突破、OI、量能和商品结构，不包含IV或期权流动性。
4. **期权结构与估值**：Delta、Gamma、统一的IV/HV相对溢价、DTE和Theta成本。
5. **情景盈亏比**：用商品目标位和失效位重估期权价值，形成最终信号等级。

任何合约推荐条件失败都不能被高发动机分、Gamma或低IV抵消，但也不能反向降级、隐藏或重排商品标的。

## 期权合约推荐门槛

这些条件只用于逐合约推荐，不作为商品标的筛选条件。逐合约资格采用严格大于：

- 当日成交量 `vol > 2000`；
- 持仓量 `oi > 1000`；
- `vol` 或 `oi` 缺失视为不合格；
- Call只使用商品多头方向行，Put只使用商品空头方向行；
- 商品方向必须与期权方向一致；
- `WAIT`、`EXHAUST`、中性方向和 `structure_confirm=CONFLICT` 不进入期权推荐候选，但商品本身仍按原有规则展示；
- `START`、`TREND`、`PREPARE` 可以继续评估，其中 `PREPARE` 必须标为“酝酿候选”，不得显示成正式启动；
- Greeks、当前权利金、标的价格、DTE或情景价位缺失时，不产生可做结论。

被拦截的合约仍可出现在完整期权链中，但返回：

- `eligible=false`；
- `grade=不可做`；
- `score=null`；
- `block_reasons`，例如“成交量不足”“持仓量不足”“趋势衰竭”“商品结构冲突”。

期权机会接口、独立期权页、期权推荐卡和导出统一使用这些字段。候选接口不得自行重新解释资格。商品机会工作台的 `focus/wait/watch/avoid` 分组不得读取 `eligible`、`block_reasons` 或期权是否存在。

## 多空数据修复

商品记录按 `(ts_code, direction)` 建立索引，不再按 `ts_code` 压成单条记录。

- Call扫描读取 `direction=long` 行的 `directional_rps20`、方向突破和启动字段；
- Put扫描读取 `direction=short` 行；
- 品种级统一结论，如 `decision_side`、`state_v2`、`structure_confirm` 和价位字段，从对应的商品决策记录合并；
- 测试必须覆盖输入顺序变化，确保先long后short或先short后long得到相同结果。

## IV和权重口径

IV贵贱统一为相对溢价：

`iv_premium_pct = (IV - HV20) / HV20 × 100`

统一分档：

- `<=0%`：10分，IV便宜；
- `(0%, 15%]`：8分；
- `(15%, 30%]`：5分；
- `>30%`：0分，IV透支。

综合信号和逐合约评分共用同一个函数，不再保留绝对百分点差和 `IV<=1.3×HV` 两套独立结论。

标的发动机不含IV和期权流动性，避免二次计权。期权流动性首先是硬门槛，通过后只作为合格合约之间的排序细项。缺失因子不通过归一化抬高总分，单独返回覆盖率。

## 目标价与盈亏比

### 商品情景价位

对买入Call：

- 当前标的价：期权对应真实月份合约收盘价；
- 目标标的价：当前价上方最近的有效压力位；
- 失效标的价：当前价下方最近的有效反转位或支撑位。

对买入Put镜像处理：

- 目标标的价：当前价下方最近的有效支撑位；
- 失效标的价：当前价上方最近的有效反转位或压力位。

复权连续价位必须按现有 `raw_close / close` 比例转换到真实月份合约口径。找不到方向正确的目标位或失效位时，情景盈亏比缺失，合约不能进入可做候选。

### 时间假设

- `START`：目标预计5个交易日到达；
- `PREPARE`：目标预计10个交易日到达；
- `TREND`：目标预计10个交易日到达。

使用 `ceil(交易日 × 7 / 5)` 转为自然日消耗，并保证剩余期限大于情景耗时。若目标日已跨越到期日，合约不可做。

### IV情景

用修正后的Black-76直接重估目标和失效情景，而不是只用一阶Greek近似。展示三组结果：

- 保守：当前IV相对下降10%，即 `IV × 0.90`；
- 基准：IV不变；
- 乐观：当前IV相对上升10%，即 `IV × 1.10`。

Delta、Gamma、Theta和Vega仍展示为风险解释项；目标价以全量重估结果为准，避免大幅行情下线性近似失真。Black-76 Theta公式同步修正，并用价格对时间的数值微分进行测试。

### 盈亏比公式

设当前期权权利金为 `P0`，保守目标情景价值为 `Pt`，保守失效情景价值为 `Ps`：

- 预期收益：`max(Pt - P0, 0)`；
- 预期风险：`max(P0 - Ps, 最小价格单位)`；
- 盈亏比：`预期收益 / 预期风险`。

当前项目没有可靠的逐期权最小价格单位时，最小风险下限先使用 `max(P0 × 1%, 0.0001)`，避免失效情景价值接近当前价格时产生无限盈亏比。结果必须标记为模型研究值。

## 最终信号分档

最终等级以保守IV情景盈亏比为准：

- `RR >= 3.0`：强烈信号；
- `2.0 <= RR < 3.0`：可做；
- `1.2 <= RR < 2.0`：观察；
- `RR < 1.2`，或目标情景价值不高于当前权利金：不可做。

阶段标签与盈亏比分开表达：

- `START + RR>=3`：启动强烈信号；
- `PREPARE + RR>=3`：酝酿高盈亏比，不得改写为START；
- `TREND + RR>=3`：趋势高盈亏比；
- 硬闸门失败时，无论RR多少均为不可做。

期权合约候选排序依次使用：资格、信号等级、保守RR、机会分、成交量、持仓量。商品标的排序保持原算法，不加入资格或期权流动性。

## 页面与接口

期权记录的 `tradability` 增加：

- `eligible`；
- `block_reasons`；
- `raw_score`；
- `score`；
- `grade`；
- `signal_level`；
- `scenario`，包含目标/失效标的价、预计天数、三组IV目标价、失效价、保守RR；
- `volume_threshold=2000`、`oi_threshold=1000`，供页面解释当前门槛。

完整期权页显示不可做原因和情景拆解。期权机会页只接收 `eligible=true` 且等级至少为“观察”的合约。商品详情中的期权推荐卡沿用同一资格，不再在前端另设一套评分逻辑；没有合格期权时只显示“暂无合约推荐”，不改变商品状态或商品机会队列。

## 测试与验收

Python测试覆盖：

- `vol=2000`不合格，`vol=2001`合格；
- `oi=1000`不合格，`oi=1001`合格；
- 缺失量仓不合格；
- `WAIT`、`EXHAUST`、结构冲突和逆趋势不合格；
- `START`、`TREND`、`PREPARE`可以进入情景评估；
- 多空行输入顺序不影响Call/Put结果；
- IV三处使用同一分档；
- ATM Call/Put Theta与数值微分一致；
- 支撑压力位正确换算到真实合约；
- DTE不足时拒绝情景；
- RR边界1.2、2.0和3.0正确分级；
- 被硬闸门拦截的合约不会进入机会接口。
- 同一组商品记录在期权链为空、量仓不足和量仓合格三种情况下，商品榜单顺序与 `focus/wait/watch/avoid` 分组完全一致；
- 期权不可做只能改变期权推荐状态，不能把 `START` 或 `TREND` 商品推入 `avoid`。

前端测试覆盖不可做原因、PREPARE专属标签、三种IV情景、强烈信号和候选排序。最终运行现有Python与Node测试，确保旧的方向、扫描、筛选和机会工作台行为没有非预期回归。

## 非目标与限制

- 本次不接入新的实时期权盘口数据源；
- 不把日线成交量和持仓量描述为真实盘口深度；
- 不实现完整IV曲面、历史IV Rank或季节性模型；
- 不把模型目标价、盈亏比或“强烈信号”描述为保证收益；
- 不改变商品价格趋势模型的既有方向公式。
