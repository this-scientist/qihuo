# 主力合约席位持仓展示设计

## 背景与目标

系统当前在商品详情的“量仓”区域固定显示“席位多空持仓：未接入”。Tushare 提供 `fut_holding` 每日成交持仓排名接口，返回合约或品种的会员成交量、持买仓、持卖仓及其日变化。本文设计将该数据接入现有收盘快照，只用于事实展示和中性解释，不参与评分、排序、筛选、候选结论或交易建议。

首版只处理每个品种当日选定的主力真实月份合约，不采集次主力，也不把主力换月前后的席位数据拼成连续序列。

官方接口文档：https://tushare.pro/document/2?doc_id=139

## 已验证约束

- 接口名为 `fut_holding`，字段包括 `trade_date`、`symbol`、`broker`、`vol`、`vol_chg`、`long_hld`、`long_chg`、`short_hld`、`short_chg` 和 `exchange`。
- 项目当前使用的自定义 Tushare 网关能够返回数值数据；已验证 `M2701.DCE` 和 `RB2701.SHF` 的合约榜单。
- 当前网关返回的部分会员中文名称已经包含不可逆替换字符。相同凭据访问 Tushare 官方入口返回 `40101`，因此首版必须支持“数值可用、名称不可用”的显式降级。
- 广期所榜单中的 `symbol` 使用小写形式；郑商所使用交易所原生三位年份合约形式的可能性必须由适配器处理并用响应内容反向校验。
- Tushare 官方文档说明，上期所查询范围包含上海国际能源交易中心合约。
- 当前 `Collector.run()` 已有 `holding -> fut_holding` 的基础映射，但实际日常更新使用 `run_focused()`，因此席位数据尚未进入当前更新任务、快照、API 或前端。

## 方案选择

采用“快照内采集”方案：行情更新确定当日主力真实合约后，逐合约获取席位排名，保存原始分区，生成汇总，并随行情快照发布。

未采用以下方案：

- 页面按需查询：依赖实时网络，页面响应慢，供应商修订后无法复现历史页面。
- 独立补采脚本：席位数据容易与行情日期或主力映射错位，长期运行也容易漏采。

## 数据流与组件边界

### 1. 主力合约输入

席位采集读取 `run_focused()` 当日已经通过校验的 `selected` 结果，仅选择 `role == "main"` 的真实月份合约。每项输入至少包含：

- 交易日期；
- 逻辑主连代码；
- 主力真实合约代码；
- 品种代码；
- 交易所；
- 主力合约总持仓量。

席位采集不自行重新判断主力合约，避免与价格和量仓页面产生不同口径。

### 2. 合约代码适配

新增单一职责的合约查询适配器，将项目标准合约代码转换为 `fut_holding` 接受的 `symbol` 和查询交易所：

- DCE、SHFE：去掉后缀并使用大写真实合约代码；
- GFEX：去掉后缀并使用小写真实合约代码；
- CZCE：生成交易所原生年份形式，同时保留标准月份信息供响应反向校验；
- INE：按官方口径以 SHFE 作为查询交易所，但只接受能严格映射回目标 INE 合约的记录。

适配器只负责构造查询和验证身份，不负责网络请求、聚合或展示。

### 3. 原始数据采集与保存

对每个主力真实合约单独调用 `fut_holding`，避免整交易所请求触及行数上限。原始结果保存到：

`raw/holding/<exchange>/<trade_date>/<contract>.csv`

每个文件同时生成完成凭据，记录接口、查询参数、行数、内容哈希和校验时间。原始文件保留接口返回的空值；不能把未上榜字段填成零。

响应必须满足：

- `trade_date` 与目标日期一致；
- `symbol` 能唯一映射回目标真实合约；
- `exchange` 与目标交易所或已定义的 INE/SHFE 路由一致；
- 数值字段为有限的非负持仓量或有限的有符号变化量；
- 同一会员在同一维度不能有冲突记录；
- 单合约返回达到供应商上限时标记不完整，不生成汇总。

### 4. 汇总器

汇总器只接受已通过身份和完整性校验的单合约原始数据，输出：

- `holding_contract`：主力真实合约；
- `holding_trade_date`：榜单交易日期；
- `holding_status`：`available`、`numeric_only`、`unavailable` 或 `invalid`；
- `holding_reason`：缺失或降级原因；
- `top20_long`：`long_hld` 非空记录降序前 20 名之和；
- `top20_short`：`short_hld` 非空记录降序前 20 名之和；
- `top20_net`：`top20_long - top20_short`；
- `top20_long_change`：前 20 多仓榜成员的 `long_chg` 之和；
- `top20_short_change`：前 20 空仓榜成员的 `short_chg` 之和；
- `top20_net_change`：`top20_long_change - top20_short_change`；
- `top20_long_concentration`：`top20_long / main_oi`；
- `top20_short_concentration`：`top20_short / main_oi`；
- `top_long_brokers`：多仓前五的会员、持仓和变化；
- `top_short_brokers`：空仓前五的会员、持仓和变化。

某榜单成员的变化字段为空时，该榜单变化汇总不可用，不把空值当作零。多仓和空仓分别独立取前 20 名；不能先按会员合并后再截取。

汇总保存到 `processed/holding/<trade_date>.json`，并由仪表盘数据构建器按主力真实合约关联到对应商品记录。

### 5. 快照与 API

原始席位分区、席位汇总和质量报告都随当日行情快照发布。`GET /api/data` 在每个商品记录中返回席位汇总，不新增页面加载时的外部请求。

历史快照保持不可变。重新补采席位数据时必须生成并发布新快照，不能在原快照目录内原地修改。

席位字段不得被任何评分、排序、筛选、阶段判定、期权资格或推荐函数读取。新增字段后更新缓存模型版本，避免 MySQL 中的旧 payload 被误判为完整数据。

## 展示与解释

商品详情的“量仓”区域用席位摘要替换固定的“未接入”文案，展示：

- 主力真实合约和榜单日期；
- 前 20 多仓、前 20 空仓和前 20 净仓；
- 多仓、空仓和净仓的当日变化；
- 多空前 20 集中度；
- 多头前五席位；
- 空头前五席位。

页面必须同时显示口径说明：“席位数据为交易所公开排名的局部口径，不代表全市场存在净多头或净空头；全市场多空总量相等。”

解释文案根据汇总事实组合，保持中性。例如：

- “前 20 席位净多，但当日净多减少”；
- “多空双方同步增仓，空方增仓更多”；
- “前 20 多仓集中度高于空仓集中度”。

解释不得出现“建议做多”“建议做空”“确认趋势”等行动性结论，也不改变页面已有商品结论。

当 `holding_status == "numeric_only"` 时，展示数值汇总并隐藏会员榜，提示“席位名称源数据异常”。当状态为 `unavailable` 或 `invalid` 时，展示原因，不显示零值占位。

## 异常与降级

- 单个合约无数据或校验失败只影响该品种的席位模块，不阻断价格行情更新。
- 主力合约总持仓缺失或非正数时不计算集中度，其他已验证汇总仍可展示。
- 任一集中度不在 `[0, 1]` 范围内时，将该合约汇总标记为 `invalid`，不展示可能存在单位或口径错误的数据。
- 会员名称为空、包含 Unicode 替换字符或明显无法显示时，状态降级为 `numeric_only`；不得猜测或自动修复会员名称。
- 换月当天只展示新主力真实合约的榜单；没有新合约榜单时显示缺失原因，不回退到旧主力。
- 质量报告分别统计成功、仅数值、无数据、身份不匹配、达到上限和数值校验失败的合约。

## 测试策略

### 单元测试

- 只从 `selected` 中选择 `role == "main"`，排除次主力和主连代码；
- DCE、SHFE、GFEX、CZCE 和 INE 的代码适配与响应反向校验；
- 多仓和空仓分别排序取前 20，前五列表正确；
- 排名字段中的空值不被当作零；
- 净仓、变化和集中度计算正确；
- 乱码会员名触发 `numeric_only` 且隐藏会员榜；
- 错日期、错合约、错交易所、冲突重复、异常数值和行数上限均拒绝汇总；
- 缺少主力总持仓时只缺集中度，不丢弃其他合法汇总。

### 管道测试

- 部分合约席位缺失时行情仍能发布，质量报告准确记录覆盖率；
- 原始分区、完成凭据和每日汇总随快照发布；
- 新旧快照各自返回对应席位数据，不发生跨日期串用；
- MySQL 缓存模型版本更新后不会返回缺少席位字段的旧 payload。

### 前端测试

- 完整数据、仅数值、无数据和无效数据四种状态均正确渲染；
- 数值格式、正负变化和前五顺序正确；
- 口径说明始终可见；
- 引入席位字段前后，商品排序、评分、阶段和期权推荐结果完全一致。

## 验收标准

- 当日有榜单的主力真实合约能在详情页看到前 20 汇总和多空前五席位；
- 次主力不会触发席位查询或展示；
- 席位数据与行情使用同一交易日期和同一主力真实合约；
- 数据缺失、乱码或不完整时有明确状态，且绝不以零或猜测名称代替；
- 历史页面从快照读取，不依赖打开页面时的网络请求；
- 席位数据不会改变任何已有评分、排序、筛选或推荐结论。
