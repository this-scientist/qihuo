# 期权量仓资格与推荐结论分离设计

## 目标

把单张期权的“量仓资格”与“是否值得推荐”拆成两个独立结论，避免把商品阶段、方向、结构、Greeks 或情景盈亏比错误描述为资格门槛。商品排序与商品机会队列继续完全不读取期权结果。

## 字段语义

- `eligible` 只检查单张期权当日量仓：`vol > 2000` 且 `oi > 1000`。缺失或等于阈值均不合格，该期权不做。
- `block_reasons` 只保存量仓资格失败原因：`成交量不足`、`持仓量不足`。
- `warnings` 保存不会改变资格的风险信息：Greeks 缺失、逆趋势、商品方向不明确、趋势衰竭、商品阶段、商品结构冲突和方向评分缺失。
- `recommendable` 表示是否进入系统候选。它要求量仓合格、情景可计算、保守 RR 至少为 1.2，并达到既有最低综合分。
- `recommendation_reasons` 保存不能推荐的原因，与 `block_reasons` 分开。

## 盈亏比展示

当情景可计算但 `RR < 1.2` 时：

- `eligible` 仍为 `true`；
- `recommendable` 为 `false`；
- 推荐原因使用实际保守 RR，格式为 `盈亏比为X，不合格`；
- 页面不得显示“未通过资格门槛”。

RR 数值采用后端情景结果，页面最多显示两位小数并去掉无意义的末尾零。情景无法计算时显示具体原因，例如“到期时间不足”，同样不归入量仓资格。

## 评分与候选

Greeks 缺失不再令 `score=null`，缺失分项按现有零分规则进入综合分，并在 `warnings` 中提示。逆趋势、商品阶段和商品结构不改变 `eligible`，但保留标签/提示，供用户判断和前端筛选。

期权机会接口和商品详情的“系统候选”只接收 `recommendable=true` 的合约。完整期权页保留所有合约，分别显示量仓资格、推荐结论、风险提示和原有综合分。商品机会工作台的 `focus/wait/watch/avoid` 分组维持现有商品规则，不受上述字段影响。

## 验收

- `vol=2000` 或 `oi=1000` 时 `eligible=false`；严格大于阈值才通过。
- Greeks 缺失、逆趋势、`WAIT/EXHAUST`、结构冲突均不改变 `eligible`。
- `RR < 1.2` 时 `eligible=true`、`recommendable=false`，并显示 `盈亏比为X，不合格`。
- `RR >= 1.2` 且评分达标的量仓合格合约可以进入机会接口。
- 期权状态不改变商品排序或机会队列。
