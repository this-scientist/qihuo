# 期货

中国商品期货/商品期权数据获取项目。

代码与数据目录位于 `期货/` 下，下文未写路径的文件名均相对于该目录；安装命令则假定在**仓库根目录**执行。

## 文件

- `config.py`：Tushare 与目录配置
- `fetch_futures_data.py`：核心数据采集脚本
- `requirements.txt`：Python 依赖
- `realtime.py`：盘中报价（新浪公开行情，只读旁路）
- `intraday.py`：盘中可执行性评分与实时排名

## 安装

在项目根目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r 期货/requirements.txt
cp .env.example .env
```

然后在 `.env` 中填写 `OAR_TUSHARE_TOKEN`。`OAR_TUSHARE_HTTP_URL` 默认使用项目已配置的数据接口。

## 首次测试

```bash
cd 期货
../.venv/bin/python fetch_futures_data.py
```

脚本默认测试 2026-09-08 大连商品交易所期货日线数据。

## 正式下载

确认测试成功后，在 `fetch_futures_data.py` 底部解除：

init_database()

## 总览页指标怎么用

总览表（`/`）里带 `?` 的列都能悬停看口径。以下是三个容易误读的列。

### 大类内相对强度（−100 ~ +100）

衡量**这个品种在自己所属大类里**的强弱，而不是全市场。

- **大类方向**：大类等权指数的 MA20 相对 5 个交易日前的斜率。`> +0.15%` 偏多、`< −0.15%` 偏空，其余震荡
- **强度**：品种相对该大类等权指数的 **20 日超额收益**，在类内排分位，再按大类方向翻转（偏空取 `100 − 分位`）
- **逆势取负**：品种自身方向与大类方向相反时，取负的是**反向强度** `−(100 − 顺势分)`，所以整列从 −100 单调到 +100

怎么读：

| 值 | 含义 |
|---|---|
| **+100** | 顺着大类方向、且在大类里最强 |
| 0 ~ +100 | 顺势强度，0 最弱 |
| 0 ~ −100 | 与大类方向相反，**越负越激进** |
| **−100** | 最强反向 |

- 单元格小字 `第k/n` 是**类内排名 / 大类成员数**。小样本大类分辨率很低：贵金属只有 2 个成员，分位只能是 0 或 100；集运欧线所在大类只有 1 个成员，直接显示 `— 类内仅1个`
- **按此列排序**：升序把逆势者顶到最前，降序把最强顺势者顶到最前；无分值的恒排最后
- 逆势格用琥珀色标出

⚠️ 别和已有的 `方向RPS20` 混：`方向RPS20` 按**品种自己**的方向翻转、基准是**全品种**；这一列按**大类**的方向翻转、基准是**同一大类内部**。

### 实时价（盘中）

来自新浪公开网页行情的最新价与买一/卖一，**交易时段每 30 秒原地刷新**，收盘后显示 `— 无盘中报价`。

⚠️ **口径陷阱**：这里的涨跌是「最新价 / **本交易日**昨结算」，而左边的「当日%」是「**最近一个收盘日**收盘 / 其昨结算」——两者不是同一天，一正一负是正常的，**不要直接相减**。悬停可看抓取时间、昨结与盘口价差。

### 可执行性（0 ~ 100，按此列降序就是实时排名）

把**前一收盘日的方向判断与支撑压力位**叠加**实时价**，判断「现在这个位置值不值得动手」。

```
可执行性 = 位置分 × 0.6 + 日线方向分 × 0.4
```

**位置分**：实时价落在「次日支撑 ~ 阻力」箱体的哪一段。用上一交易日振幅做单位（推进度 0 = 顺方向的近端价位，1 = 远端）：

| 顺向推进度 | 状态 | 分 |
|---|---|---|
| ≥ 1.3 | 远离目标位（追单风险） | 25 |
| 1.0 ~ 1.3 | 刚破目标位 | 75 |
| 0.7 ~ 1.0 | 接近目标位 | 35 |
| 0.3 ~ 0.7 | 区间中部 | 50 |
| **0 ~ 0.3** | **顺向边缘（回调/反弹到位）** | **90** |
| −0.5 ~ 0 | 逆势越界 | 30 |
| < −0.5 | 反向破位 | 8 |

**方向分**（日线状态）：`START 100 / TREND 85 / PREPARE 60 / EXHAUST 30 / WAIT 20`。

空头完全镜像：反弹到阻力才是好入场（90），跌破支撑算「接近目标位」（35）。

- **日线无方向的品种不给分、不参与排名**，不会伪造位置分把它顶上榜
- 悬停可看完整拆解：次日支撑/阻力/突破/反转、推进度、位置分、方向分、合成权重
- 逆势/追单的格用琥珀色标出，强势加粗

⚠️ 这是**规则分，不是胜率，也没有回测**。0.6/0.4 的权重和那七档划分都是经验值，觉得不合就改 `intraday.py` 里的 `EXEC_WEIGHT_*` 与 `position_band()`。

### 次日价位怎么来的

四个价位全部由**最后收盘日那一根 K 线**算出，是一套经典的枢轴点（pivot）公式：

```
重心 e =（高 + 低 + 开 + 2×收）/ 5

支撑 = 2e − 高          阻力 = 2e − 低
突破 = e + 振幅         反转 = e − 振幅        （振幅 = 高 − 低）
```

以铜（20260923：开 111979.67 / 高 111979.67 / 低 111008.46 / 收 111128.61）验算：

| 价位 | 计算 | 结果 |
|---|---|---|
| 重心 e | (111979.67 + 111008.46 + 111979.67 + 2×111128.61) / 5 | **111445.00** |
| 支撑 | 2×111445 − 111979.67 | 110910.34 |
| 阻力 | 2×111445 − 111008.46 | 111881.55 |
| 突破 | 111445 + 971.21 | 112416.21 |
| 反转 | 111445 − 971.21 | 110473.79 |

上表是**复权口径**；页面显示的是乘过复权因子的真实合约价（见下文「价格口径」）。

四条容易踩的：

1. **「目标位」= 远端价位**：多头是**阻力**，空头是**支撑**
2. **箱体宽度恰好等于上一交易日振幅**：`阻力 − 支撑 = 971.21`，而 `高 − 低 = 971.21`。所以「推进度」的单位是「昨天一整天的波动幅度」，0 在支撑、1 在阻力——这是用振幅而不是 ATR 做单位的原因
3. **`反转 / 突破` 的基准是重心、不是箱体边**，所以它们距箱体边只有约半格（本例 0.45 / 0.55 格），**具体比例由当日 K 线形状决定，不是固定值**
4. **`突破` 价位落在推进度 ≈1.55**，已经属于「远离目标位（25 分）」，不是「刚破目标位」。如果你的体系把 `突破` 当买入信号，会跟这一列打架——这是有意的：打到那儿就算追单

各状态对应在箱体的哪一段：

- 支撑↔阻力之间是箱体，切三段：**顺向边缘**（靠支撑，多头）/ **区间中部** / **接近目标位**（靠阻力）
- 阻力以上 → **刚破目标位**（1.0~1.3），再往上 → **远离目标位**（>1.3）
- 支撑以下 → **逆势越界**（−0.5~0），再往下 → **反向破位**（<−0.5）

### 哪些状态适合日内

| 状态 | 日内 | 为什么 |
|---|---|---|
| **顺向边缘 90** | ⭐ 最好 | 价格回到支撑（做多）/ 反弹到阻力（做空），**止损就放箱体边外一点点**，只有零点几格距离，风险回报最好 |
| **刚破目标位 75** | 可以 | 触发明确，但止损要放回箱体内，距离更远；日内假突破多（尤其尾盘） |
| **接近目标位 35** | 顺向别做 | 顺着日线方向已经追尾。但反过来在这个位置**反手**（阻力做空 / 支撑做多）反而是好位置——这一列是「顺日线方向」打分，反手不在它的框架里 |
| **区间中部 50** | ❌ 避开 | 上下都没边界参照，止损没地方放，最容易两头挨打。日内做这个就是刮头皮 |
| **逆势越界 30** | 别做 | 价格已越过支撑（对多头），说明日线方向的日内延续性弱 |
| **反向破位 8** | 别做 | 日线方向已被否定 |

⚠️ **这个位置分不是为日内设计的**。它衡量的是「顺着日线方向**入场的位置**好不好」，是给波段/持仓入场用的。真要做日内，还缺三个维度：

1. **波动够不够**：箱体窄说明昨天振幅小，日内可能没肉，扣掉手续费和价差白做。目前只用 `MIN_BOX_RATIO` 拒绝「退化到接近十字星」的箱体，**没有**要求「足够大」
2. **盘口价差占箱体的比例**：现在有买一/卖一了，能算 `价差 / 箱体宽度`。价差吃掉箱体一大块时，日内进出就是给做市商送钱，这一项**可以直接筛掉**
3. **时段**：临近 14:45 和夜盘品种收盘节奏不同，同一位置在开盘和尾盘的意义不一样

建议的「日内适配度」口径（**尚未实现**）：

```
日内适配度 = 箱体宽度 / 价格        （波动够不够）
           − 盘口价差 / 箱体宽度    （摩擦大不大）
           − 时段惩罚               （临近收盘）
```

门槛不达标就直接标「日内不宜」，而不是硬给一个分数。这样「可执行性」管**方向与位置的性价比**，「日内适配度」管**今天这单到底做不做得动**，两个维度分开、互不污染。

## 实时数据

### 数据源

| 接口 | 状态 |
|---|---|
| 新浪 `hq.sinajs.cn`（内盘期货） | ✅ 使用中，带买一/卖一，覆盖 SHFE/DCE/CZCE/GFE/INE 全部主连 |
| Tushare `rt_fut_min` / `ft_mins` | ❌ 需单独开权限（返回 `2002010`），且**不带盘口** |
| 商品期权实时 | ❌ 未找到可用免费源 |

### 接口

- `GET /api/quotes`：当日主连的原始报价（最新价、买一/卖一、昨结、持仓、成交）
- `GET /api/execution`：报价 + 可执行性排名（含次日价位与各项分值）

**两者都是只读旁路**：不写 MySQL、不写快照、不参与任何评分。收盘口径的 `data_hash` 与历史验证的可复现性不受影响，收盘决策仍完全基于收盘数据。

### 限制

- 新浪是**非官方网页接口**，无 SLA，可能改格式或限频。代码按「解析失败 → 降级为空报价 → 前端显示不可用」兜底，格式变更仍需人工跟进
- 只有**一档盘口**（买一/卖一），没有五档深度，判断不了大单冲击
- **期权端没有解决**：`option_analysis.py` 里「日线观察，待核实实时盘口」依然成立，期权自身的买卖价差仍缺，滑点估不准
- 报价时间在单元格悬停里，超过 5 分钟未更新会标注「报价已过期」

### 价格口径（改这一块务必注意）

日线价位（支撑/阻力/突破/反转）来自**复权连续**，而盘中报价是**真实合约价**，两者差一个复权因子——68 个品种里有 60 个因子明显偏离 1（焦煤 1.63、生猪 1.62、集运欧线 0.65）。`intraday.price_scale()` 用 `raw_close / close` 把价位换算到真实口径；**因子缺失时拒绝打分而不是给猜测值**。

## 期权候选验证页与 AI 分析

`/scanner.html` 的「自定义品种」页签可任选品种，用与「做多/做空候选」**完全相同**的列与详情面板复核它的期权综合分、结构分解、组合信号与候选合约（后端 `GET /api/candidate`）。

详情面板底部有「AI 一键分析」（`POST /api/ai/analyze`）：把技术面、商品结构、期权候选与**本地支撑压力位**一起发给 DeepSeek，返回头寸意见、依据、失效条件、风险与产业逻辑。使用前在 `.env` 填写：

```bash
DEEPSEEK_API_KEY=sk-xxxx
DEEPSEEK_MODEL=deepseek-v4-flash
```

三处必须知道的限制：① DeepSeek 官方 API **不提供联网检索**，产业逻辑是模型固有知识、非实时，可能过时或错误，且不参与任何评分；② 模型给出的支撑/压力位**不可复现**，只与本地计算结果并列对照；③ 分析是研究参考，不是可执行交易指令。本地支撑压力位由 `price_levels.py` 用**真实月合约未复权历史**计算（前高前低、整数关口、ATR 通道、成交密集区），可复现、作为事实基准。

## 期权机会总览页

`/opportunities.html`（顶部导航「期权机会」）把**所有可做期权按品种分组一次性列出**，不用再逐个点开 T 型报价找。

后端 `GET /api/options/opportunities` 复用逐合约的可做性评分（优 ≥80 / 良 ≥65 / 可关注 ≥50），按品种分组、组内按评分排序，只下发 ≥50 的合约（约 465KB，全量 11MB）。

页面上的筛选（默认值）：

- 可做性阈值 **≥65（良）**，可切 ≥50 / ≥80
- 期限 **7–120 天**，另有 0–10 末日轮 / 11–30 / 31–60 / 61–120 快捷键
- 「仅顺势」默认勾选。逆趋势合约评分**硬封顶 55**，所以取消勾选时需同时把阈值降到 ≥50 才看得到，页面会提示
- 每组默认只列前 5 张，可展开全部；点任意合约跳到该品种 T 型报价页并自动带上筛选条件、展开该合约损益图

⚠️ 数值是**日线参考值，不是可成交报价**——系统没有盘口，不确认买卖价差与滑点（期权端的实时行情见上文「实时数据」，目前仍未解决）。

## 数据管道注意

- 「更新行情」在写 MySQL 的同时**必须发布文件快照**（`publish_snapshot`）。历史验证（`/research.html`）与重算走的是快照目录，漏了这一步会报 `Requested dashboard snapshot unavailable`。相关回归见 `tests/test_persistence.py`
- 改了 payload 字段后要**刷新 MySQL 缓存**，否则前端会看到整列空值：缓存按 `model_version` 判定有效性，新增派生列不会自动失效。服务内重算只对当前进程的活跃日期生效，持久修复跑 `scripts/mysql_import.py`（它绕过缓存读、用当前代码重建后写回）
- 静态资源响应带 `Cache-Control: no-cache`，避免浏览器出现「新模块 + 旧模块」混用导致整页白屏（ES module 依赖报 `does not provide an export named ...` 就是这类问题，强制刷新一次即可）
